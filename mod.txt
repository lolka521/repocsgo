Playing together (when the project is multiplayer, this is part of getting it listed, not an extra):
A multiplayer project goes up as a multiplayer mashup. Work this out before you submit anything; don't list it as single player and come back to it. Melty gives every player of a multiplayer mashup a join link, lists open games on the mashup's page, and can put a joiner straight into the host's game. Set recipe.multiplayer so it does:
- maxPlayers: the most players one game takes, when the project has a limit. Use the project's real number.
- connect: how Melty connects players without anyone typing an address. It works when the game (or the mod) does two things, so build them in if you are making the mod, or find them if they already exist:
  1. Hosting says where it is. When a game opens to others, it writes its address (a host name or IPv4 address, with a port if needed) to a log file, on a line with fixed words right before it. Tell Melty with connect.address: {log: "{localappdata}/MyMod/logs/latest.log", after: "Hosting at "}. If hosting needs a switch, give it with connect.hostEnv (environment variables) or connect.hostArgs (launch arguments); "{port}" is a free port Melty picks. Melty applies these on every Play.
  2. Joining takes the address at start. Use whichever the game supports: connect.joinArgs (launch arguments), connect.joinEnv (environment variables), connect.joinFile {path, key} (a key=value line in a .properties/.ini/.cfg/.txt file the game reads at start; Melty empties it again for solo play), or connect.joinUri (a steam:// link). "{address}" is the host's address.
  Paths start with a folder token such as {game}, {localappdata} or {minecraft-instance}. Environment variables must be the mod's own (for example MYMOD_JOIN), never system ones.
- If the game can only be joined by hand (an in-game menu), still set recipe.multiplayer with maxPlayers and leave connect out; add connect.address alone if the address appears in a log, so Melty can show it to joiners to paste.
- Players behind home routers cannot reach each other by local address. Use the game's own relay or lobby system, or bundle one the license allows; do not tell players to forward ports.
- game_info says, for the engines Melty knows, how a mod reads who is in a session and the clock they share: start there when the mod has to find its players.
- validate_recipe checks this section. Before saying multiplayer works, test hosting and joining with two running copies (two PCs, or a second instance on this one) and tell me exactly what you tested. If you could not test joining, say so and leave connect out rather than guessing.
